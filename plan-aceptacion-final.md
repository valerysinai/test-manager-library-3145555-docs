# Plan previo de aceptación ampliada y demostración

Base Docs main `eba3a91`; rama `feature/docs-final-acceptance`. Los seis forks contienen ya
los cambios del cierre anterior. Esta etapa responde a la petición de completar la revisión
de pantallas/teclado y preparar la demostración, sin cambiar el producto.

El plan ejecutable de infra se publica antes de ampliar el recorrido real en
`feature/final-acceptance`. Se comprobarán pantallas, estados vacíos/errores, nombres de controles,
contraste, teclado y persistencia con API real y datos sintéticos. Si se reproduce un defecto,
App tendrá una corrección mínima en otra rama de main y se fijará su revisión en infra.

La guía en Docs contendrá preparación con los README existentes y recorrido manual por rol,
resultados esperados y una lista sin marcar para la persona que presenta. No llevará credenciales,
no cambiará reloj del equipo y remitirá a C-04/tool para producir vencidos por API en una base demo.

La evidencia conservará fuente exacta, informes seguros, capturas sin datos de autenticación y
estados anteriores/finales. Se distinguirán inspección visual, automatización y actuación humana.
Las tres ramas de revisión serán del fork y usarán feature/. No se fusionarán automáticamente.
La fecha original de entrega y las limitaciones del evaluador siguen vigentes.
